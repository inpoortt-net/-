# STM32 密码锁小设备（test 0.1）

> **STM32F103C8T6 + SSD1306 OLED（128×64）+ 4 按键 + 无源蜂鸣器 + 红/绿双状态灯**
> 一个从零手写、逐步迭代出来的“菜单式密码锁”：OLED 中文界面、密码校验与输错锁定、时间显示与断电保存、按键音效与状态灯提示。
> 本项目为学习/考核作品：源码全部带中文注释，配套学习资料在 `docs\` 目录。

---

## 一、它能做什么（功能一览）

| 功能 | 说明 |
| --- | --- |
| **主页时钟** | 显示日期、星期、时间（hh:mm:ss）；时间每整分钟自动存入 Flash，重启后恢复 |
| **主菜单** | 按 OK 进入；上下键选择；30 秒无操作自动回主页 |
| **密码锁** | 默认密码 `1234`（可改）；UP/DOWN 调数字、OK 确认一位、长按 OK 提交校验 |
| **输错锁定** | 连错 3 次锁 30 秒：倒计时界面 + 红灯慢闪；**到期不清零、只再给 1 次机会；只有输对密码才清零**；错误次数存 Flash，断电重启仍在锁定 |
| **修改密码** | 独立界面：输入新密码 → 再输一次确认 → 两次一致才保存（存 Flash，掉电不丢） |
| **声音反馈** | 无源蜂鸣器 PWM 变调：按键短嘀 / 正确上行叮咚 / 错误下行嘟呜 / 提示两短声 |
| **状态灯** | 绿灯=正确、红灯=错误、锁定期间红灯慢闪（开漏输出、低电平点亮） |
| **非阻塞设计** | 按键/蜂鸣器都在中断里跑；界面延时全部用“截止时刻比较”，屏幕刷新约 0.1 秒期间也不会丢按键 |

## 二、硬件连接

| 部件 | 连接 |
| --- | --- |
| OLED（I2C） | **PB6=SCL、PB7=SDA**（100kHz；驱动自动识别 0x3C/0x3D） |
| 按键 ×4 | **UP=PA0、DOWN=PA1、OK=PA2、BACK=PA3**（内部上拉，按下=低电平） |
| 蜂鸣器 | **PB0**（TIM3_CH3 PWM；无源、低电平触发模块，VCC 接 3.3V、CH Polarity=Low） |
| 状态灯 | **绿灯=PA4、红灯=PB1**（开漏、低电平点亮；接线：3.3V→LED→电阻→引脚） |
| 时钟 | HSE 8MHz 晶振 → PLL ×9 → **72MHz**（APB1=36MHz） |

## 三、软件结构

**分层**：驱动层（oled / key / buzzer / led）→ 服务层（clock / settings）→ 应用层（ui）；主循环只调 `ui_task()`。

| 文件 | 职责 |
| --- | --- |
| `Core\Src\oled.c` | SSD1306 驱动：显存缓冲、画点/矩形、ASCII + 汉字混排（含 UTF-8 解码） |
| `Core\Src\key.c` | 按键驱动：定时扫描 + 四态消抖 + 事件队列（短按/长按/连发） |
| `Core\Src\buzzer.c` | 蜂鸣器音效：PWM 变调 + 后台音序播放 |
| `Core\Src\led.c` | 状态灯：亮/灭/慢闪（上电自配开漏引脚） |
| `Core\Src\clock.c` | 软件时钟：走时 + 日历进位 + 每整分钟存 Flash |
| `Core\Src\settings.c` | 密码与错误次数的 Flash 存取（“账本”机制） |
| `Core\Src\ui.c` | 界面大脑：页面状态机（主页 / 菜单 / 密码锁 / 修改密码） |
| `Core\Inc\oledfont.h`、`oledfont_cn.h` | 点阵字库（纯数据：8×16 ASCII 95 字、16×16 汉字 48 字） |

## 四、用到的数据结构与算法（都能在《大话数据结构》里找到对应）

没有刻意堆砌算法，但这个项目把几个**最基础、最常用**的结构与算法思想用到了实处——每一个都是“因为真的需要”才用的：

### 1. 队列 —— 按键事件队列（key.c）
- 按键在 1ms 中断里被扫描，而界面有时正忙（刷屏一次约 0.1 秒），没法当场处理；
- 用一个 **8 格环形队列**先把“短按 / 长按 / 连发”事件存起来，主循环有空再取；
- 环形回绕用 **位与运算 `& (8-1)`** 代替取余（队列长度取 2 的幂，回绕 = 一次位运算）；
- 中断只动队头、主循环只动队尾（单生产者单消费者），**不需要加锁**。

### 2. 状态机 —— 三处典型
- **按键消抖**：空闲 → 按下消抖 → 按住 → 松开消抖，四态；长按/连发是“按住”态里的计时分支；
- **界面页面机**：主页 → 菜单 → 密码锁 / 修改密码；每个页面各有按键处理与绘制函数；
- **密码流程**：等待 → 输入中 → 正确 / 错误 → 锁定倒计时；
- 好处：任何时刻“当前处于哪一步”一目了然，逻辑不乱。

### 3. 位图与位运算 —— OLED 显存（oled.c）
- 屏幕 1024 字节 = 128×64 的**位图**：每个字节管竖直 8 个像素（SSD1306 页格式）；
- 画一个点 = 找到字节、算出 bit、用 `|=` / `&=~` 点亮或熄灭；
- 字库同样按此格式存成数组（**数组 + 查表**）。

### 4. 查表法 —— 到处都在用
- 汉字 / ASCII 字库：按码点**顺序查找**表项；
- 星期名、月份天数表、蜂鸣器音符表……都是“提前把答案写成数组，用时直接查”，比一堆 if 更好维护。

### 5. 校验和（Checksum）—— Flash 记录的“防伪章”
- 每条存入 Flash 的记录（时间 / 密码 / 错误次数）都带一个字节的**累加和**；
- 上电读取时校验；写坏或写了一半的记录直接跳过——数据完整性的入门做法。

### 6. 追加写 + 循环复用 —— Flash“账本”（clock.c / settings.c）
- 1KB 的 Flash 页切成 **64 个 16 字节“格子”**，每次保存**追加一条**，而不是每次擦除；
- 写满一整页才擦一次、从头再来——像**环形缓冲**一样循环使用，把有限的擦写寿命均摊到 64 次保存；
- 读取时从最后一格往前**倒序扫描**，第一条校验通过的就是最新记录。

### 7. 日历数学 —— 时间的算法（clock.c）
- **闰年规则**：能被 4 整除且不能被 100 整除，或能被 400 整除；
- **月份天数表** + 二月特判；
- **蔡勒公式**：由“年-月-日”直接算出星期几（经典数学公式）；
- 走时的“秒→分→时→日→月→年”就是标准的**进位处理**（本质上和加法器进位链同一思想）。

### 8. 进制分解与编码 —— 显示前的数据处理
- 数字转字符串：逐位 `%10` 拆数字字符（**进制分解**基本功）；
- **UTF-8 解码**：把 1~3 字节的中文字符还原成 Unicode 码点（位运算拼接），再去字库查表。

### 9. 软件滤波 —— 消抖的本质
- 按键“抖动”就是一段噪声信号；**连续 20ms 都是同一电平才认账**，等价于一个最简单的去毛刺 / 低通滤波。

> **没有用到**：链表、树、哈希表、排序——不是不会，而是当前规模（最多几十条记录、几十个汉字）**用不上**，硬上反而增加出错面。工程原则：**合适 > 花哨**。

## 五、可靠性设计（为什么它“稳”）

- **掉电保存**：时间 / 密码 / 错误次数都在 Flash；
- **断电不逃**：输错锁定重启后继续计时；
- **非阻塞**：屏幕刷新期间按键不丢（中断扫描 + 事件队列）；
- **防呆**：密码要输两遍才生效；错误次数只有“输对”才清零；
- **全程测试**：电脑端按键逻辑模拟测试（`tools\key_test\`，6 项全过）+ 每版本编译 0 错 0 警 + git 全历史可追溯。
