# 第 0 节　先学方法：怎么"读"一个函数？

别一行一行硬念。按这四步走：

1. **看签名**——函数名、参数、返回值，先猜它是干嘛的。
   例：`key_process(idx, raw)`：处理"第 idx 个键的一次采样"，`raw` 是这次读到的电平；
2. **看输入输出和副作用**——进来什么、出去什么，会不会顺手改全局变量、写 Flash、点灯；
3. **抓主线**——找到核心的 `switch` / `if`，其他都是配合；
4. **"删了会怎样"**——假设删掉某行/某段，程序会出什么毛病。**这是检验真懂的标准**，面试也爱这么问。

下面每个函数都按这个套路来。

# 第 1 节　`key_process` —— 消抖状态机的"心脏"

先看身份：

```c
static void key_process(uint8_t idx, uint8_t raw)
```

- `idx`：第几个键（0~3，对应 UP / DOWN / OK / BACK）；
- `raw`：这次采样读到的状态（**1 = 手按着**，0 = 松开）；
- 返回：无——它直接修改 `s_keys[idx]` 里的状态机现场。

> 小设计：为什么"读引脚"和"处理状态"要分开？`key_tick` 负责采数、`key_process` 负责逻辑——分开后这个函数是**纯逻辑**，可以不接板子就测试（我们的电脑端模拟测试就靠这个性质）。

## 第一段：空闲状态——"找按下"

```c
case KEY_ST_IDLE:
    if (raw)
    {
        k->state = KEY_ST_PRESS_DEB;   // 疑似按下，先记着
        k->deb_ms = KEY_SCAN_MS;       // 消抖计时从 5ms 起
    }
    break;
```

- `if (raw)`：只有"读到按下"才有下文；松开就什么也不做；
- **不立即发事件**——先转入"按下消抖"，信任要等 20ms 再给；
- `deb_ms = KEY_SCAN_MS`（5ms）：为什么不是 0？因为这一轮采样本身就是一份 5ms 的"证据"。

> **删了会怎样**：如果 IDLE 直接发"按下"——抖动期间的每个毛刺都会触发一次。

## 第二段：按下消抖——"连续核对"

```c
case KEY_ST_PRESS_DEB:
    if (raw)
    {
        k->deb_ms = (uint16_t)(k->deb_ms + KEY_SCAN_MS);
        if (k->deb_ms >= KEY_PRESS_MS)   // 连续 20ms 都是按下
        {
            k->state = KEY_ST_PRESSED;   // 确认按下，进入"按住"
            k->hold_ms = 0;              // 开始计"按了多久"
            k->repeat_ms = 0;
            k->long_sent = 0;
        }
    }
    else
    {
        k->state = KEY_ST_IDLE;          // 只是抖了一下，不算数
    }
    break;
```

- 核心思想：**不是"等 20ms 再看一次"，而是"每 5ms 看一次、连续四次都对才认"**——每次采样都是一票"证据"；
- 中途读到松开（else）→ 打回 IDLE，之前的证据全部作废；
- 确认时把三个计时器清零：`hold_ms`（按了多久）、`repeat_ms`（连发计时）、`long_sent`（长按发过没）——**新的一次按压从零开始**。

> **面试点**：为什么用"加法"而不是"记第一次按下的时刻再做差"？
> 加法只数扫描次数、不依赖时间基准；而且和扫描周期解耦（改 `KEY_SCAN_MS`，这段逻辑不用动）。

## 第三段：按住状态——长按与连发

```c
case KEY_ST_PRESSED:
    if (raw)
    {
        k->hold_ms = (uint16_t)(k->hold_ms + KEY_SCAN_MS);
        if (!k->long_sent)
        {
            if (k->hold_ms >= KEY_LONG_MS)   // 满 800ms
            {
                key_push(idx, KEY_EVENT_LONG);
                k->long_sent = 1;            // 只发一次
                k->repeat_ms = 0;            // 连发从这一刻开始计
            }
        }
        else
        {
            k->repeat_ms = (uint16_t)(k->repeat_ms + KEY_SCAN_MS);
            if (k->repeat_ms >= KEY_REPEAT_MS)   // 每 200ms
            {
                key_push(idx, KEY_EVENT_REPEAT);
                k->repeat_ms = 0;
            }
        }
    }
    else
    {
        k->state = KEY_ST_RELEASE_DEB;   // 疑似松开，去消抖
        k->deb_ms = KEY_SCAN_MS;
    }
    break;
```

- `long_sent` 是"一次性开关"：长按只发一次，发完进入连发节奏；
- 连发计时在长按那一刻清零——所以顺序是"先长按 800ms，之后每 200ms 连发"；
- 读到松开**不立即发短按**，先转入"松开消抖"——松开也会弹跳。

> **删了会怎样**：删掉 `long_sent` 判重 → 每 5ms 重复发一次长按（刷屏式提交）；长按处不重置 `repeat_ms` → 连发节奏错乱。

## 第四段：松开消抖——"回旋镖"设计

```c
case KEY_ST_RELEASE_DEB:
    if (raw)
    {
        k->state = KEY_ST_PRESSED;       // 原来是抖了一下，又按住了
    }
    else
    {
        k->deb_ms = (uint16_t)(k->deb_ms + KEY_SCAN_MS);
        if (k->deb_ms >= KEY_RELEASE_MS)
        {
            k->state = KEY_ST_IDLE;
            if (!k->long_sent)
            {
                key_push(idx, KEY_EVENT_SHORT);   // 补发短按
            }
        }
    }
    break;
```

两个"高级点"：
1. **回到 PRESSED**：按住中接触抖了一下 → 进这里 → 20ms 内又按着 → **回到 PRESSED，一切照旧**（长按计时接着数、不产生多余事件）。这就是"四态"比"两态"高级的地方；
2. **补发短按有条件**：`if (!k->long_sent)`——**发过长按的，松手不补短按**，否则一次长按出两个事件。

> **面试点**：把这两点讲出来，基本能证明消抖是你自己写的，而不是抄的。

## 收尾：default 兜底

```c
default:
    k->state = KEY_ST_IDLE;   // 理论上到不了这，兜底
    break;
```

防御性编程：万一状态变量被写坏，也能回到 IDLE 重新开始，不会卡死。

## 把这个函数"讲"出来（60 秒版）

> "key_process 是按键状态机的心脏，四个状态：空闲、按下消抖、按住、松开消抖。每 5ms 调一次，每个键一个独立状态机。按下要连续 20ms 都对才确认；按住期间数两个表：800ms 发长按，之后每 200ms 发连发；松开也要消抖 20ms，松手补发短按——但发过长按就不补。它本身不返回事件，事件统一进队列。"

# 第 2 节　`key_tick` + 队列"三位一体"

## key_tick：采数 + 分发

```c
void key_tick(void)
{
    s_scan_div++;
    if (s_scan_div < KEY_SCAN_MS) return;   // 1ms 进来一次，5ms 才扫一轮
    s_scan_div = 0;
    for (i = 0; i < KEY_COUNT; i++)
    {
        raw = (HAL_GPIO_ReadPin(s_key_port[i], s_key_pin[i]) == GPIO_PIN_RESET) ? 1 : 0;
        key_process(i, raw);
    }
}
```

- 它在 SysTick 中断里跑（每 1ms 进来一次），用 `s_scan_div` **分频**成 5ms 一轮——扫描周期和中断频率解耦；
- 4 个键循环：读引脚 → 转成 1/0（1=按着）→ 交给 `key_process`；
- 为什么中断里干这个不慌？4 次读引脚 + 4 个小状态机 = 微秒级。

## key_push：往队列放（中断专用）

```c
static void key_push(uint8_t key, uint8_t event)
{
    uint8_t next = (uint8_t)((s_q_head + 1) & (KEY_QUEUE_SIZE - 1));
    if (next != s_q_tail)
    {
        s_queue[s_q_head] = (uint16_t)(((uint16_t)event << 8) | key);
        s_q_head = next;
    }
}
```

- 环形队列：`head` 写到哪、`tail` 读到哪，转一圈即满；
- `& (KEY_QUEUE_SIZE - 1)` = 位运算"取模 8"（队列大小必须是 2 的幂，就是为了这招）；
- `if` 检查：`next == tail` 说明要撞上读指针 = 满 → **放弃入队**（丢新不丢旧）；
- 一个 16 位打包俩信息：高 8 位事件、低 8 位按键号。

## key_get_event：从队列取（主循环专用）

```c
uint8_t key_get_event(uint8_t *key, uint8_t *event)
{
    if (s_q_head == s_q_tail) return 0;      // 空了
    v = s_queue[s_q_tail];
    s_q_tail = (uint8_t)((s_q_tail + 1) & (KEY_QUEUE_SIZE - 1));
    *key = (uint8_t)(v & 0xFF);
    *event = (uint8_t)(v >> 8);
    return 1;
}
```

- 两个"出参"把按键号和事件带回去；
- **为什么不用加锁**：`head` 只有中断写、`tail` 只有主循环写——各自单点写、对方单点读，天然安全（单生产者 / 单消费者）。

> **面试连招**："中断里为什么不处理界面？因为中断要短。事件靠无锁环形队列传给主循环，单放单取所以安全；满了丢新事件、绝不阻塞。"
> **删了会怎样**：不写 `& (KEY_QUEUE_SIZE-1)` → 指针越界；不写满判断 → 手快连按时覆盖旧事件。

2. `long_sent` 的作用？没它会发生什么？
3. 为什么"发过长按就不补发短按"？
4. 队列的 head / tail 分别由谁写？为什么不用锁？

# 第 3 节　`digit_edit_key` —— 两个密码页共用的"数字输入编辑器"

先看数据结构（ui.c 顶部）：

```c
typedef struct
{
    uint8_t count;                  // 已确认几位
    uint8_t digits[PWD_MAX_LEN];    // 已确认的数字
    uint8_t current;                // 正在调的当前位 0~9
} digit_edit_t;
```

三个字段正好对应屏幕上三样东西：`count` 个 `*`、1 个"正在调的数字"、一串 `_`。

## 先看"服务协议"

```c
static uint8_t digit_edit_key(digit_edit_t *e, uint8_t key, uint8_t event)
// 返回：0=已处理；1=长按OK"提交"；2=一位都没输入时按了BACK
```

它用返回值"上报事件"，**不直接做提交/返回**——密码页和改密码页各自拿到 1 或 2 后自己决定怎么做。这是"组件化"的关键一步：输入组件只管输入，业务由页面管。

## 逐段拆

```c
case KEY_UP:
    e->current = (uint8_t)((e->current + 1) % 10);
    s_dirty = 1;
    break;
case KEY_DOWN:
    e->current = (uint8_t)((e->current + 9) % 10);   // "减 1"的取巧写法
    s_dirty = 1;
    break;
```

- 0~9 循环滚动；DOWN 用 `+9 % 10` 代替 `-1`——避开"0-1 变成负数"的坑（C 语言里负数取模还是负数，这是个经典小知识）；
- 每改一下 `s_dirty = 1`：请求重画屏幕。

```c
case KEY_OK:
    if (event == KEY_EVENT_SHORT)
    {
        if (e->count < PWD_MAX_LEN)          // 边界检查：满了按不进去
        {
            e->digits[e->count] = e->current; // 当前数字"落格"
            e->count++;
            e->current = 0;                   // 归零，准备下一位
            s_dirty = 1;
        }
    }
    else if (event == KEY_EVENT_LONG)
    {
        return 1;                             // 提交信号，交给页面
    }
    break;
```

```c
case KEY_BACK:
    if (event == KEY_EVENT_SHORT)
    {
        if (e->count > 0)
        {
            e->count--;
            e->current = e->digits[e->count]; // 把删掉的数字"捡回来"继续调
            s_dirty = 1;
        }
        else
        {
            return 2;                          // 空输入时按 BACK → "想返回"
        }
    }
    else if (event == KEY_EVENT_LONG)
    {
        digit_edit_reset(e);                   // 一键清空
        ui_show_hint("已清空");
        buzzer_notice();                       // 两短声
        s_dirty = 1;
    }
    break;
```

- 删位时"把数字捡回来"是个贴心细节：删错了能接着调，不用重新滚一圈；
- 长按 BACK = 清空 + 提示 + 提示音——"手感细节"集中在这几行。

> **删了会怎样**：删掉"捡回来"那行 → 删位后当前数字归零，改回刚才的值要重新数一遍（功能还在、体验变差——这种"体验级"取舍面试可以讲）。

# 第 4 节　`ui_pwd_page_submit` —— 校验三步骤

```c
static void ui_pwd_page_submit(void)
```

## 第一步：门槛

```c
if (s_pwd_edit.count < PWD_MIN_LEN)     // 不足 4 位
{
    ui_show_hint("至少4位");
    buzzer_notice();
    s_dirty = 1;
    return;                              // 只提示，不算错误
}
```

不足 4 位**不算错**（不然手滑会白扣一次机会）——"门槛和错误分开"。

## 第二步：双比对

```c
settings_get_password(pwd, &pwd_len);    // 从内存拿真密码（settings 模块维护）
if (s_pwd_edit.count != pwd_len) ok = 0; // 先比位数
else
{
    for (i = 0; i < pwd_len; i++)
    {
        if (s_pwd_edit.digits[i] != pwd[i]) { ok = 0; break; }   // 再逐位比
    }
}
```

先比位数、再逐位比，任何一位不对立即 `break`——不用全比完。

## 第三步：两条路

```c
if (ok)
{
    s_pwd_fail_count = 0;                 // 对 → 错误次数清零（顺带写 Flash）
    settings_set_fail_count(0);
    s_pwd_result = PWD_RESULT_OK;
    s_pwd_result_timer = HAL_GetTick() + MSG_SHOW_MS;   // 展示 2 秒
    led_green();                          // 绿灯
    buzzer_success();                     // 叮-咚
}
else
{
    s_pwd_fail_count++;
    settings_set_fail_count(s_pwd_fail_count);   // 错 → 立即写 Flash：断电也不逃

    if (s_pwd_fail_count >= PWD_FAIL_MAX)        // 第 3 次 → 锁定
    {
        s_pwd_result = PWD_RESULT_LOCKED;
        s_pwd_lock_until = HAL_GetTick() + PWD_LOCK_MS;   // 记下"解锁时刻"
        led_blink(1);                          // 红灯慢闪
    }
    else
    {
        s_pwd_result = PWD_RESULT_FAIL;
        s_pwd_result_timer = HAL_GetTick() + MSG_SHOW_MS;
        led_red();
    }
    buzzer_fail();                             // 嘟-呜
}
```

两个关键设计：
1. **错误次数当场写 Flash**——"断电重启锁定仍有效"的地基；
2. **锁定不是"睡 30 秒"**，而是记了一个**未来的时刻**（`s_pwd_lock_until`）——倒计时界面每秒拿"现在"和它做减法。这就是非阻塞。

## 附：锁定到期逻辑（在 `ui_task` 里）

```c
else if (s_pwd_result == PWD_RESULT_LOCKED && ui_time_up(s_pwd_lock_until))
{
    if (s_pwd_fail_count >= PWD_FAIL_MAX)
    {
        s_pwd_fail_count = (uint8_t)(PWD_FAIL_MAX - 1);  // 压回"上限-1"：只再给 1 次
        settings_set_fail_count(s_pwd_fail_count);
    }
    s_pwd_result = PWD_RESULT_NONE;     // 解锁，但【不清零】
    led_off();
    buzzer_confirm();                   // 一声"可以重新输入了"
}
```

这段就是 v0.7.3 的"故事主角"。讲给面试官时把**为什么改**带上：
"初版是到期自动清零（每次白送 3 次机会）；用户实测后提出应该'输对才清零'；我改成了到期不清零、只再给 1 次——再错一把立刻重新锁。"

> **面试点（完整版）**："错误计数在每次输错时写 Flash、只在输对 / 改密码成功时清零；锁定是记时刻不是延时；到期只再给 1 次——这是从测试反馈迭代出来的策略。"

# 第 5 节　`clock_add_seconds` —— 一条"进位多米诺"

先看签名：

```c
void clock_add_seconds(uint32_t seconds)   // 时钟往前走 seconds 秒
```

## 关键小设计：进门先"记账"

```c
uint8_t last_minute = s_time.minute;   // 先记住"进门时的分钟"
...
if (s_time.minute != last_minute)      // 出门前对一下
{
    clock_flash_save();                // 分钟变了才存 Flash
}
```

- 为什么不在"进位那一层"发现分钟 +1 就直接存？**分层**：进位逻辑只管进位，存储时机统一在函数出口判断——一个事实一个家，读起来也清爽；
- 为什么"分钟变了才存"？每秒都存的话，Flash 擦写次数很快耗光（每页约 1 万次的账，手册第 6 章算过）。

## 进位多米诺（节选）

```c
while (seconds > 0)
{
    seconds--;
    s_time.second++;
    if (s_time.second >= 60)
    {
        s_time.second = 0;  s_time.minute++;
        if (s_time.minute >= 60)
        {
            s_time.minute = 0;  s_time.hour++;
            if (s_time.hour >= 24)
            {
                s_time.hour = 0;
                s_time.weekday = (s_time.weekday + 1) % 7;   // 星期跟着日期走
                s_time.day++;
                if (s_time.day > clock_month_days(s_time.year, s_time.month))
                {
                    s_time.day = 1;  s_time.month++;
                    if (s_time.month > 12) { s_time.month = 1; s_time.year++; }
                }
            }
        }
    }
}
```

- 就是一层套一层的"满了就进位"；所谓复杂，只是层数多；
- `weekday` 不重算公式——**它跟着日期走**：每跨一天 +1 就行（公式只在"校时 / 上电恢复"时用一次）；
- 每月天数交给 `clock_month_days()`：查表 + 闰年 2 月特判（`clock_is_leap_year`：四年一闰、百年不闰、四百年再闰）；
- 为什么按秒循环（笨办法）而不是数学一次到位？简单、直观、不会错；调用方每次也就传 1~2 秒，开销忽略不计——**能用笨办法做对，就不用聪明办法做错**。

> **删了会怎样**：不判断 `minute` 变化 → 每秒写一次 Flash（寿命飞快耗尽）；闰年判断漏掉 → 2 月 29 日直接写错。

# 第 6 节　`clock_flash_save` / `clock_flash_load` —— 账本怎么记、怎么翻

## save：三步走

```c
static void clock_flash_save(void)
{
    // 第 1 步：从前往后找第一个"空格子"
    for (i = 0; i < CLOCK_SLOT_COUNT; i++)
    {
        if (s->magic == 0xFFFFFFFFUL) { addr = ...; need_erase = 0; break; }
    }
    // 第 2 步：装填记录（含校验和）
    slot.magic = CLOCK_MAGIC;  slot.year = ...;  slot.checksum = clock_slot_checksum(&slot);
    // 第 3 步：解锁 →（写满则整页擦除）→ 按"半字"逐个写 → 上锁
    HAL_FLASH_Unlock();
    if (need_erase) { HAL_FLASHEx_Erase(...); addr = CLOCK_FLASH_ADDR; }
    p = (const uint16_t *)&slot;
    for (i = 0; i < 8; i++)
    {
        HAL_FLASH_Program(FLASH_TYPEPROGRAM_HALFWORD, addr + i * 2, p[i]);
    }
    HAL_FLASH_Lock();
}
```

逐点讲：
- **为什么找第一个空格子**：账本是顺序追加的，前面的格子都被老记录占了；第一个 `magic == 0xFFFFFFFF` 就是"下一个空位"；
- **一个都找不到** → `need_erase` 保持 1 → 整页擦掉重来（所有格子回到 0xFFFFFFFF）；
- **为什么按"半字"（2 字节）写**：STM32F1 的 Flash 编程粒度就是半字（硬件规定），16 字节拆成 8 次写；
- **写失败就 break**：不重试、不报错——下次上电校验不过会自动跳过它，丢的只是一条记录（**优雅降级**）；
- **Unlock / Lock 成对**：Flash 平时锁着防误写，动它之前解锁、写完马上上锁。

## load：从后往前"翻账"

```c
for (i = CLOCK_SLOT_COUNT - 1; i >= 0; i--)     // 从最后一格往前找
{
    if (s->magic == CLOCK_MAGIC &&
        s->checksum == clock_slot_checksum(s) &&     // 校验和要对
        s->month >= 1 && s->month <= 12 && ...)      // 数值还要合理
    {
        取出来用；return 1;
    }
}
return 0;   // 一条合法的都没有
```

- 最新记录一定在**最后面**——从后往前找，第一条合法记录就是"最新账"；
- "合法"有**三层**：魔数对 + 校验和对 + 数值范围合理——不信任 Flash 里的任何数据。

> **面试点**："Flash 存储为什么不用覆盖式写？因为 Flash 只能整页擦除。我用追加式账本 + 校验和：擦除次数摊到 64 次写才一次，任何一条写坏也只丢一条。"

# 第 7 节　`settings_flash_write` —— 一套代码，两个模块共用

## 通用写函数

```c
static void settings_flash_write(const uint8_t *rec)   // 收"16 字节裸数据"
```

- 和 `clock_flash_save` 第 3 步几乎一样：找空格 →（满则擦页）→ 8 个半字写进去；
- 为什么参数是**字节指针**而不是具体结构体？**通用**——密码记录、次数记录都是 16 字节，一个函数都能写；
- 上层两个专用函数只管"装填"：

```c
settings_flash_save(digits, len) → 装填 'PWD1' 记录 → settings_flash_write(...)
settings_fail_save(count)        → 装填 'FAIL' 记录 → settings_flash_write(...)
```

**分工**：装填管"内容长什么样"，写入管"怎么进 Flash"——一层一个职责。

## 读的时候：三层验证（以密码为例）

```c
if (s->magic == SETTINGS_MAGIC &&
    s->checksum == settings_slot_checksum(s) &&      // 1) 魔数 + 校验和
    s->len >= 4 && s->len <= SETTINGS_PWD_MAX)       // 2) 长度合法
{
    for (j...) if (s->digits[j] > 9) break;          // 3) 每位必须是 0~9
}
```

任何一层不过 → 跳过这一条，继续往前找。

> **删了会怎样**：不校验 `checksum` → 写坏的数据可能被当成密码（自己把自己锁死）；不查 `digits ≤ 9` → 乱码也能当密码。

## 一个"顺序"细节

无论改密码还是记错误次数，都是**先改内存、再写 Flash**：
- 内存值 = 运行中用的"现行值"；
- Flash = 断电后的"存档"；
- 先内存后 Flash，保证"运行中永远用最新的"。

> **面试点**："密码和错误次数共用同一页 Flash，用魔数区分记录类型；读的时候魔数、校验和、数值合法性三层验证——不信任存储介质。"

# 第 8 节　`oled_refresh` —— 一屏 0.1 秒的"水流"

```c
void oled_refresh(void)
{
    uint8_t tx[OLED_WIDTH + 1];                                  // 129 字节一包
    uint8_t area_cmds[7] = { 0x00, 0x21, 0x00, 0x7F, 0x22, 0x00, 0x07 };
    const uint8_t *p = oled_buffer;

    oled_write(area_cmds, sizeof(area_cmds));   // 先"圈地"：显示区域 = 整屏
    tx[0] = 0x40;                               // 控制字：后面是"数据"
    for (page = 0; page < 8; page++)
    {
        memcpy(tx + 1, p, OLED_WIDTH);          // 拷一页 128 字节
        oled_write(tx, sizeof(tx));             // 发一包：1 控制字 + 128 数据
        p += OLED_WIDTH;
    }
}
```

- `area_cmds` 七个字节怎么读：`0x00`（控制字=命令）＋`0x21 0x00 0x7F`（列地址 0~127）＋`0x22 0x00 0x07`（页地址 0~7）——**先圈地，再倒数据**；
- 为什么每包第一个字节是控制字：I2C 上要告诉屏幕"这串是命令还是数据"；
- 每包 129 字节 = 1 控制字 + 128 列，共发 8 包；
- **0.1 秒的账**：一千多字节（8 包 ×129 + 命令）@100kHz ≈ 90~100 毫秒；这期间主循环在"等"，但按键不丢（扫描在中断里）——所以"没变化就别刷"（s_dirty）；
- 可讲的优化方向：① 只刷变化区域（局部刷新）；② I2C 提速到 400kHz（刷新缩到约 25ms）。

> **删了会怎样**：不发 `area_cmds` → 屏幕从上次停的地方接着写，画面错位花屏。

# 第 9 节　`oled_utf8_next` + `oled_show_char` —— 汉字是怎么被"翻译"的

```c
static uint16_t oled_utf8_next(const char **p)
{
    const uint8_t *s = (const uint8_t *)(*p);
    if (s[0] < 0x80) { code = s[0]; *p += 1; }                    // ASCII：1 字节
    else if ((s[0] & 0xE0) == 0xC0 && s[1] != 0)
    { code = ((s[0] & 0x1F) << 6) | (s[1] & 0x3F); *p += 2; }     // 2 字节字符
    else if ((s[0] & 0xF0) == 0xE0 && s[1] != 0 && s[2] != 0)
    { code = ((s[0] & 0x0F) << 12) | ((s[1] & 0x3F) << 6) | (s[2] & 0x3F); *p += 3; }   // 汉字：3 字节
    else { code = '?'; *p += 1; }                                  // 不认识的：跳 1 字节，显示 ?
    return code;
}
```

- 掩码的意思：`0xE0 = 11100000`，检查首字节是否"`110` 开头"（两字节模式）；`0xF0` 检查"`1110` 开头"（三字节模式）——**这是 UTF-8 的规则本身**，不是我们发明的；
- `s[1] != 0`、`s[2] != 0` 是**防越界**：字符串万一以半个汉字结尾，也不会读过头（防御性编程）；
- 返回的 `code` 是 Unicode 码点，交给 `oled_show_text` 分流：`<0x80` 走 8x16 英文，否则查 16x16 汉字表。

`oled_show_char` 里的一行细节：

```c
byte = font[(row < 8) ? col : (col + 8)];   // 上半页第 col 列 / 下半页第 col 列
```

一个 8x16 字符的 16 字节 = 上半页 8 列 + 下半页 8 列；画第 row 行时：row<8 取前半（`+col`），row≥8 取后半（`+col+8`）。

> **删了会怎样**：去掉越界检查 → 半截汉字会让指针读越界（画面乱码，甚至死机）。

# 第 10 节　`buzzer_tick` —— 音乐在"后台"走路

```c
void buzzer_tick(void)
{
    s_tick_div++;
    if (s_tick_div < 10) return;   // 1ms 进来，10ms 才走一步
    s_tick_div = 0;

    if (s_seq == 0) return;        // 没在播 → 什么也不做
    if (s_note_left > 10)
    {
        s_note_left = (uint16_t)(s_note_left - 10);
        return;                    // 当前音符还没播完
    }
    s_seq_pos++;                   // 换下一个音符
    if (s_seq_pos >= s_seq_len)    // 整段播完
    {
        s_seq = 0;
        buzzer_silent();           // 回到安静
        return;
    }
    buzzer_play_note(&s_seq[s_seq_pos]);
}
```

- 每 10ms"走一步"：音符剩余时长减 10；减不动了（≤10）就切下一个音符——误差最多 10ms，耳朵听不出来；
- **`s_seq = 0` 当"停机标志"**：一个指针搞定"在播 / 没播"两种状态；`buzzer_play()` 里"先置 0 再开播"就是借它防止中断捣乱（手册第 5 章细讲过）；
- 中断里永远只做"减一减、换一个"这种小事——真正决定音调的是 `buzzer_play_note` 里改 ARR 的那两行。

> **删了会怎样**：不递减 `s_note_left` → 一个音符永远播不完；播完不 `buzzer_silent()` → 最后一个音"卡"在响。

# 第 11 节　`ui_task` 全走读 —— 主循环"八步曲"逐条对照

```c
void ui_task(void)   // 主循环 while(1) 里唯一的常驻函数
```

按注释顺序过一遍，重点看"为什么是这个顺序"：

| 步 | 做什么 | 为什么放这个位置 |
| --- | --- | --- |
| 1 | `while (key_get_event(...))` 清空按键队列 | **响应优先**：先把"人按的事"处理完 |
| 2 | 走时（`clock_add_seconds`） | 时间相关，紧随其后 |
| 3 | 密码页：结果展示到点清空 / 锁定到点解锁 | 页面状态的"到期检查" |
| 4 | 设置页：结果到点（成功回密码页 / 失败回第一步） | 同上 |
| 5 | 临时提示到点消失 | 小定时任务 |
| 6 | 菜单闲置 30 秒回主页 | 兜底交互 |
| 7 | `led_task()` 慢闪翻面 | 灯的小计时 |
| 8 | `if (s_dirty) 重画` | **最贵的事放最后**：刷屏要约 0.1 秒，只在必要时做 |

三个"为什么"：
- **为什么 1 放最前**：用户按键的反馈越快越好；
- **为什么 8 要用 `s_dirty` 守门**：一轮里可能好几个地方都改了状态（步骤 3/4/5 各设过一次 `s_dirty`），**攒到最后一并画一次**——不重复刷屏；
- **为什么没有 `HAL_Delay`**：全部用"到点检查"（拿"现在"和"截止时刻"比）——主循环永远在转，永远响应。

> **把整个程序"串"成一句话（面试压轴版）**：
> "SysTick 中断每 1ms 扫按键、推音乐；主循环 ui_task 先清按键队列、再做到期检查、最后按 s_dirty 重画。数据上：用队列把中断和主循环解耦，用 Flash 账本把密码和时间存住，用状态机把按键消抖和页面切换管起来。"
