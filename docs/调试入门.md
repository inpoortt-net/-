# 调试入门（Keil 实操）—— 让程序"停下来给你看"

> 配套：《核心代码逐行精读》、《面试问答手册》第三组（现场 Debug）。
> 用法：对着电脑边看边做；每个操作都写清了"点哪里、按什么键"。
> 说明：以 Keil MDK5（µVision）+ 你的调试器（ST-Link 类）为准；菜单以英文版为准。
>
> 版本：v1.1（2026-10-05 审查修订：实操一断点打法、Run to main 提示）

---

# 0. 为什么要会调试？

- 考核说了：现场可能给个小问题让你找——**"你会先检查哪里、怎么验证"就是评分点**；
- 更实际的是：调试器能让程序"**停下来**"，你亲眼看到变量值、状态机跳转——**看懂代码的最强外挂**；
- 本文只讲最实用的四件事：**进调试、打断点、单步走、看变量**。不碰 HardFault / 寄存器底层（考核明说不考）。

# 1. 先确认调试器能用（配置一次，长期受用）

1. 板子接好调试器，SWD 四根线：**SWDIO、SWCLK、GND、3.3V**（对应板子的 PA13 / PA14）；
2. Keil 菜单 **Options for Target**（魔术棒图标）→ **Debug** 页；
3. 右侧选你的调试器（如 **ST-Link Debugger**）→ 点旁边的 **Settings**：
   - **Debug** 标签：Port 选 **SW**；Sw Device 区里能看到一串 IDCODE = 芯片认出来了；
   - **Flash Download** 标签：确认有编程算法（下载固件用的）；
4. 点 **OK** 保存。

> **连不上？按顺序查**：① 线序和接触（最常见）→ ② 板子供电 → ③ 换根线 / 换 USB 口 → ④ 调试器驱动（设备管理器看有没有黄叹号）→ ⑤ PA13 / PA14 有没有被别的功能占用。

# 2. 进入 / 退出调试

| 操作 | 怎么做 |
| --- | --- |
| 进入调试 | 菜单 **Debug → Start/Stop Debug Session**，或按 **Ctrl+F5** |
| 退出调试 | 再按一次 **Ctrl+F5** |
| 全速运行 | **F5**（或 Run 按钮） |
| 停止运行 | 工具栏的 Stop（红色停止按钮） |

进入调试后界面会变样：多出一排调试按钮、代码左边出现灰色边条（打点用）。程序默认会先跑到 `main()` 停下（如果没停在 `main`，检查 **Options for Target → Debug** 里的 **Run to main()** 选项）。

# 3. 断点：让程序"停在你指定的那行"

**打 / 取消断点**：在代码行号左边的**灰色边条点一下**（出现红点）；或光标停在该行按 **F9**。

- 全速运行（F5）命中断点会**暂停**，黄色箭头指着"下一行要执行的代码"；
- 右键红点可以 **Disable**（变空心 = 保留但不生效）；
- **Ctrl+F9** = 启用/禁用当前行断点；**Ctrl+B** = 打开断点管理窗口。

> ⚠️ **重要提醒**：调试**暂停**时，整个程序都停了——中断也不跑。所以别指望"暂停着还能按按键"；正确姿势是"**先全速运行，再按键/操作触发断点**"。

# 4. 单步：一步一步走

| 操作 | 快捷键 | 干什么 |
| --- | --- | --- |
| Step（跟进去） | **F11** | 执行一行；遇到函数调用**跟进去** |
| Step Over（跳过去） | **F10** | 执行一行；函数调用**当一行跳过** |
| Step Out（跑完当前函数） | **Ctrl+F11** | 从函数里"一口气跑回"调用处 |
| Run to Cursor（冲到光标行） | **Ctrl+F10** | 全速跑到光标所在行再停 |

用法建议：**先 F10 粗走，关键函数再 F11 进去**——不然会在 HAL 库的代码里"迷路"。

# 5. 看变量：Watch 窗口 + 鼠标悬停

1. 菜单 **View → Watch Windows → Watch 1** 打开监视窗口；
2. 在 Name 栏**输入变量名**回车（如 `s_pwd_edit`、`s_pwd_fail_count`、`raw`）；
3. 暂停 / 单步时值会刷新；**鼠标悬停**在变量上也能直接看；
4. 结构体 / 数组点前面的 **+** 展开（如 `s_pwd_edit.digits`、`s_keys[0]`）；
5. 值还能**手动改**（双击数值）——调试时很有用。

三个实战注意：
- **局部变量**要"程序停在该函数里"才能看到（跑到别处会显示不在范围）；
- 看不到 / 显示乱：把优化等级调低——**Options for Target → C/C++ → Optimization 选 Level 0**，重新编译再调试（调完可以改回去）；
- 想看**内存**：**View → Memory Windows → Memory 1**，地址栏输入 `&oled_buffer` 就能看到 1024 字节显存的原始数据。

# 6. 实操一：抓按键（把"消抖"看活）

> **先懂一个坑**：`key_process` 每 5ms 会被 4 个键各调一次——断点不能随便打，
> 否则程序会"疯狂停"。正确思路：**打"事发的瞬间"，不打"每次路过的地方"**。

**① 抓"按下开始的那一瞬间"**

1. 在 `k->state = KEY_ST_PRESS_DEB;` 这一行打断点（是 `KEY_ST_IDLE` 分支里那一行——它只在"从空闲检测到按下"时执行一次）；
2. 按 **F5 全速运行**；
3. 按一下 **UP 键** → 命中；
4. Watch 里加 `idx`、`raw`、`k->state` → 看到 `idx = 0`、`raw = 1`（此刻 `state` 还是 IDLE，下一步才变）；
5. 按 **F10** 单步一步 → `state` 变成 `PRESS_DEB`，消抖开始；
6. 继续 F5：只要一直按住，就不会再停在这里（已经不在 IDLE 了）——想再命中，松手再按一次。

**② 抓"确认按下（20ms 凑满）"**

- 把断点移到 `k->state = KEY_ST_PRESSED;` 这一行 → F5 → 按住 UP 不放 → 约 20ms 后命中 → 看 `k->deb_ms` 已经到 20。

**③ 抓"长按 800ms"**

- 断点移到 `key_push(idx, KEY_EVENT_LONG);` → F5 → 按住不放 → 约 0.8 秒后命中 → 这就是"长按事件发生"的现场。

> 三处看完，你已经"亲眼见过"消抖状态机全程了。
> 断点不生效？确认：① 正处于调试会话（不是普通下载运行）② 代码是最新编译的。

# 7. 实操二：抓"密码比对"

1. 全速运行，先在屏幕上输几位数字（**注意：这时程序在全速跑**）；
2. 在 `ui_pwd_page_submit` 的比对处打断点；
3. 长按 OK 提交 → 命中；
4. Watch 里加 `s_pwd_edit.digits` 和 `pwd`，展开逐个对比——**亲眼看到"逐位比对"在干什么**；
5. **F10** 单步往下走，看 `ok` 从 1 变 0（或保持 1）的那一瞬间。

# 8. 实操三：抓"存 Flash"与"看显存"

- **存 Flash**：在 `settings_flash_save` 开头打断点 → 改一次密码并提交 → 命中 → Watch 里展开 `slot`（magic、len、digits、checksum）；
- **看显存**：Memory 1 地址栏输 `&oled_buffer`；暂停时那 1024 字节就是当前画面——画了字的区域会**非零**。

# 9. 进阶小技巧（现场 Debug 的加分项）

1. **断点的"次数"与"条件"**：**Ctrl+B** 打开断点窗口，双击已有断点：
   - **Count**：设 100 → 第 100 次命中才停——**专门对付"每 5ms 一次"的高频断点**；
   - **表达式**（如 `idx == 3`）→ 条件成立才停；
   - **Command**：写 `printf("hit\n")` → 命中时只在输出窗口打印、**不停机**（相当于不打断程序的"探针"）。
2. **Run to Cursor（Ctrl+F10）**：不用打点，"冲到这一行"；
3. **改了代码要重新编译 + 重新进调试**才生效。

# 10. 现场 5 个场景：用调试器怎么查（速查）

| 场景 | 第一步（不上电脑） | 用调试器怎么验证 |
| --- | --- | --- |
| 正确密码绿灯不亮 | 看灯脚 / 极性；可用 `LED_TEST_ALWAYS_ON` 体检 | 在 `led_green()` 处打断点：**能命中** = 软件没毛病 → 查灯路；**不命中** = 逻辑没走到 → 查代码 |
| 某个按键没反应 | 换其他键对比；查线 | 在 `k->state = KEY_ST_PRESS_DEB;` 那行打条件断点（条件 `idx == 3`）：按该键不命中 → 输入链路（硬件 / 线）；命中 → 再看事件有没有进队列 |
| 正确却总报错 | 想想"最近改过什么" | 在比对处看 `digits` vs `pwd`：现场抓"到底哪一位不对" |
| 清空后输入异常 | 复现一遍看现象 | 在 `digit_edit_reset` / `digit_edit_key` 看 count / current 的值 |
| 蜂鸣器对错提示反了 | 听 + 翻音色表 | 在 `buzzer_success` / `buzzer_fail` 断点：看该响哪个的时候实际调的是谁 |

> 提醒：现场不一定有电脑让你调试——**"排查思路"比"会用调试器"更重要**；调试器是平时的外挂，现场用眼睛 + 万用表也要能讲思路（见《面试问答手册》第三组）。
