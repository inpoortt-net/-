# 第一组　保命 3 题（考核里明说会问）

## Q1　GPIO 是什么？输入和输出有什么区别？HAL_GPIO_ReadPin 在干什么？

**回答要点：**
- GPIO = 通用输入输出口，就是单片机上一个个可以"读电平 / 给电平"的引脚；
- **输入**：引脚电平由外部决定，程序去"读"（读回来 0 或 1）——我们的按键就是输入；
- **输出**：程序去"控制"引脚——我们的灯就是输出；
- `HAL_GPIO_ReadPin(端口, 引脚)` 就是"读这个引脚现在是什么电平"，返回 0（低）或 1（高）。按键按下 = 低电平，所以读出来 0 表示"按着"。

**可能追问：**
- "上拉电阻是干嘛的？" → 没人按的时候把引脚温柔地拉到 3.3V，防止"悬空"乱跳（下面 Q4 详细讲）；
- "为什么不用浮空输入？" → 浮空就像一根**没系住的绳子**悬在空中，风一吹（电磁干扰）就飘——电平不确定，读到的值不可信。

## Q2　为什么按键需要消抖？

**回答要点：**
- 按钮内部是金属片，按下/松开的**瞬间会弹跳** 5~20ms，电平抖来抖去；
- 不处理的话，按一下会被程序当成"按了好几下"；
- 我们的做法：**连续核对 20ms**——每 5ms 扫描一次，连续 4 次都读到"按下"才算真按下；松开同理；
- 关键是**没用延时**：全程状态机 + 计时，不卡程序。

**可能追问：**
- "为什么不用延时 20ms 再读一次？" → 那会把整个程序卡住 20ms（屏幕、按键全停）；状态机是"每 5ms 看一眼、记着状态"，一毫秒都不浪费；
- "20ms 怎么定的？" → 弹跳一般在几毫秒到二十毫秒，人手最快大约 100ms 按一次——20ms 刚好能分开"抖动"和"真按"。
- "不等待，怎么确认它稳了 20ms？" → 把"等"拆成"抽查"：每 5ms 看一次、记一票，**连续 4 票都是"按下"**（攒满 20ms）才算数；中途一票不对就作废重来。状态变量（state / deb_ms）就是记账本——CPU 不需要站在原地等，每轮只花几微秒；
- "两态不够用吗？" → 两态（按下/松开）碰到"按住中接触抖一下"会误判成"松开又按下"、多出事件；四态里的 RELEASE_DEB 能"回到 PRESSED、当无事发生"。

## Q3　OLED 为什么用 I2C？定时器或 PWM 有什么用？

**回答要点：**
- I2C 只要两根线（SCL 时钟 + SDA 数据），比并口（十几根）、SPI（4 根）都省引脚；屏幕自带驱动芯片，我们只管"喂数据"；100kHz 速度够每秒刷一屏；
- **定时器**：硬件自动数数、自动产生波形，CPU 不用盯着——我们的蜂鸣器就用 TIM3 产生方波；
- **PWM**：调**频率**变音调（叮 / 咚），调**占空比**变强度；我们的"叮-咚"就是频率变化的方波排队播出来的。

**可能追问：**
- "I2C 两根线为什么还要上拉电阻？" → I2C 的引脚是"开漏"结构，只能拉低、不能主动拉高，靠上拉电阻把线"拉回"高电平（Q11 细讲）。

# 第二组　从你的项目"深挖"（老师最爱这么问）

> 网上几乎所有嵌入式面试经验都提到同一条：**面试官喜欢从项目里往深处挖**——"为什么这样设计？"。下面每一题都是你项目里真实做过的决定。

## Q4　按键为什么接 GND + 内部上拉，而不是接 3.3V？

- 接法：按钮一端接引脚、一端接 GND；引脚开**内部上拉**；
- 没按时：上拉把引脚拉到高电平（读到 1）；按下：被拽到 GND（读到 0）；
- 好处：省一个外部电阻、接法简单；"按下 = 低电平"这个约定全项目统一。

**追问："如果接 3.3V 呢？"** → 那要配下拉输入、按下读到 1；两种都对，我们选了省事的那种。

## Q5　事件队列为什么不用加锁？队列满了怎么办？

- 放事件的只有中断（生产者），取事件的只有主循环（消费者）——各管一头，天然不打架，所以不用锁；
- 队列能存 8 个事件，正常操作根本用不满；满了就丢弃新事件（宁可丢，不阻塞）；
- 这也是"中断轻、主循环重"分工的体现。

## Q6　中断里为什么不能干重活？

- 中断会**打断一切**，跑久了整个系统都卡；
- 我们的中断里只做两件小事：扫一眼按键、推一步音乐——都是微秒级；
- 密码判断、画屏这种"重活"全留给主循环。

## Q7　屏幕为什么"先画显存，再整屏推"？直接写屏不行吗？

- 直接写屏：每次小改动都要发 I2C（几十毫秒），屏幕还会闪；
- 先画显存：内存里随便改（微秒级），改完统一推一次（约 0.1 秒），稳定不闪；
- 配合 `s_dirty`：没变化就不推——省时间省总线。

## Q8　密码为什么要存 Flash？为什么带"魔数 + 校验和"？

- 存 Flash：掉电不丢（Flash 不需要电池也能记住内容）；
- **魔数**（'PWD1' / 'FAIL'）：一眼看出"这格子里存的是什么"；
- **校验和**：数据万一写坏，读的时候能发现并跳过——不然密码变乱码，自己把自己锁死。

## Q9　为什么"每分钟"存一次时间，不是每秒？

- Flash 有寿命（每页大约 1 万次擦写），写得越勤耗得越快；
- 每分钟一次：断电最多丢 1 分钟读数，寿命却宽裕几十倍——这是"**精度换寿命**"的取舍。

## Q10　错误次数为什么要存 Flash？

- 不存的话：错 3 次锁定，断电重启就"满血复活"，锁定形同虚设；
- 存了以后：**断电重启仍在锁定中**（重新计 30 秒）——这是防绕过的关键设计。

## Q11　LED 为什么用开漏输出？（推挽和开漏的区别）

- **推挽** = "有推有拉"：引脚能主动输出高或低，驱动能力强；
- **开漏** = "只能拉低，或者放手"：输出高时是"放手"（高阻态），电平由外部决定；
- 我们的接法：`3.3V → LED → 电阻 → 引脚`，拉低 = 导通点亮；开漏在这里更稳，不会和外部电源"顶牛"；
- 代码里 `led_pins_config()` 上电自配引脚，不依赖 CubeMX 的配置。

**追问："还有哪里用了开漏？"** → I2C 总线（PB6/PB7）本身就是开漏结构，靠上拉电阻回到高电平。

## Q12　PWM 是怎么"变调"的？

- 定时器硬件在数数，数到某个值翻转引脚，就形成方波；
- 方波**频率 = 音调**（2kHz 尖、1kHz 沉）；我们改的是定时器的 ARR（频率 f 对应 `ARR = 1MHz/f - 1`）；
- **占空比** = 高电平占的比例，我们的蜂鸣器固定 50%；不响时把占空比设 0（配合低电平极性，不耗电）。

**可能追问：**
- "定时器计数频率为什么按 72MHz 算，不是 APB1 的 36MHz？" → STM32 的规则：APB1 分频不为 1 时，挂在它上面的定时器时钟会自动 ×2（36×2=72MHz）；所以 PSC=71 时计数频率 1MHz、ARR 决定音调。
- "ARR 开了预装载（AutoReloadPreload）是干嘛的？" → ARR（和占空比的 CCR）都是**双缓冲**：写入的新值在**下一个周期边界**才生效——改频率时不会输出"半截周期"的畸形脉冲（防爆音、波形干净）。
- "PSC、ARR、Pulse 这三个数当初是怎么定的？" → 见《代码导读手册》§1.4 的表：PSC=71 凑 1MHz（公式好算）；ARR=369 / Pulse=185 是上电占位（≈2.7kHz / 50%），运行时由代码按音符改写。

## Q13　为什么要用状态机？为什么不用操作系统（RTOS）？

- 页面切换、按键处理都是"有限个状态 + 跳转条件"，状态机写起来清楚、好调试（4 个页面 / 按键 4 个状态都是状态机）；
- 不用 RTOS：这个规模用"主循环 + 中断"完全够；引入 RTOS 反而增加复杂度和出错面；
- 一句话：**合适的规模用合适的技术**，而且我能讲清每一处调度。

## Q14　（理解验证题）"如果要求密码必须 6 位，你改哪里？"

- `ui.c` 顶部的 `PWD_MIN_LEN`：4 → 6；
- 顺带要改：`settings.c` 里的默认密码 1234（4 位）会不符合新规则，要换成 6 位；
- 提示语"至少4位"也要跟着改。
- 这种题考的是"你是否真的知道数据流"——能答出"动哪几个文件"就赢了。

## Q15　为什么把主频跑到 72MHz？

- HSE 8MHz 晶振 ×9 倍频 = 72MHz，F103 的经典档位；
- 快 = 刷屏、按键扫描、音序都从容；代价是功耗略增、Flash 读等待周期变 2（HAL 自动处理）。

## Q16　密码输入为什么只显示 `*`？

- 防"偷看"（虽然演示设备没人偷看，但这是密码类界面的基本素养）；
- 界面上只显示"已确认几位"和当前正在调的数字，不显示真实密码——考核也明确说"不要求显示真实密码"。

# 第三组　现场 Debug 模拟（考核的可选加分项）

> 通用心法：**先看现象 → 再分"硬件还是软件" → 用最小改动验证**。不要一上来乱翻代码。

## Q17　"正确密码输对了，绿灯不亮"怎么查？

1. 先看红灯状态：两个灯都没反应 → 先怀疑供电/接线；只有绿灯不亮 → 问题大概率在绿灯这条路；
2. 硬件：检查绿灯脚是否插紧；用 `LED_TEST_ALWAYS_ON`（改成 1 重烧，两灯常亮）一眼判断线/极性/电阻；
3. 软件：看 `ui.c` 输对密码后有没有调 `led_green()`，再看 `led.c` 的极性函数。
（这个坑我们**真遇到过**：当时就是绿灯插线问题，靠"常亮测试"查出来的——真实经历就是加分点。）

## Q18　"某个按键突然没反应"怎么查？

1. 换按其他键：只有这一个键不灵 → 问题锁定在这个键；
2. 查线：杜邦线松/断最常见——拔下重插或换一根；也可以用镊子把该引脚短接到 GND，程序有反应 = 芯片和代码没毛病，是按钮/线的问题；
3. 查代码：`key.c` 里这个键的编号和引脚对不对（PA0~PA3）。

## Q19　"密码明明正确却一直显示错误"怎么查？

1. 回忆"最近改过什么"：改密码后没保存成功？烧录时选了整片擦除（把密码清了）？
2. 用默认密码 1234 试一次——能过就说明密码被清过/被改过；
3. 看比对代码：位数比对 + 逐位比对两处，是不是哪里被改反了。

# 尾声：答题三部曲

1. **先说结论**——一句话回答"是什么 / 为什么"；
2. **再说做法**——项目里具体怎么实现的，指得出文件和函数；
3. **最后说取舍**——为什么这么选、有没有更好的（"如果继续做，我会加……"）。

> 不会的题：诚实说"这块我了解得不深，我的理解是……"，比硬编强得多。
> 想练手：随时跟我说"来一道"，我按这本抽题考你。
